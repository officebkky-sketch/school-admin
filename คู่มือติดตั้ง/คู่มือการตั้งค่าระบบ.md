# 📘 คู่มือการตั้งค่าระบบสำหรับโรงเรียนใหม่ (Multi-School Setup Guide) 🏫✨

คู่มือฉบับนี้ใช้สำหรับแนะนำคุณครูผู้ดูแลระบบไอทีของ **โรงเรียนใหม่** ที่ได้รับโปรแกรมแอปพลิเคชัน (.exe) ไปใช้งาน และต้องการตั้งค่าระบบหลังบ้าน (Database & LINE Bot) ของตนเองให้แยกเป็นอิสระ 100% โดยมีขั้นตอนแบ่งเป็น 5 ตอนหลักแบบจับมือทำค่ะ:

---

## 💾 ตอนที่ 1: การสมัครและตั้งค่าฐานข้อมูล (Supabase Setup)

ฐานข้อมูลของแอปนี้ใช้บริการของ **Supabase (PostgreSQL)** ซึ่งเปิดให้บริการฟรี สามารถสมัครและสร้างตารางได้ง่ายๆ ดังนี้ค่ะ:

1. **สมัครสมาชิก**: เข้าไปที่เว็บ [https://supabase.com](https://supabase.com) -> คลิก **Sign Up** (แนะนำให้สมัครด้วยบัญชี GitHub หรือ Google)
2. **สร้างโครงการใหม่ (New Project)**:
   * คลิก **New Project**
   * เลือก Organization ของตนเอง
   * **Name**: ตั้งชื่อสถานศึกษาของคุณครู (เช่น `Ban Kuan School Database`)
   * **Database Password**: ตั้งรหัสผ่านของฐานข้อมูล (กรุณาจดบันทึกเก็บไว้ด้วยนะคะ)
   * **Region**: เลือก `Singapore` (ใกล้ประเทศไทยที่สุดและทำงานเร็วที่สุดค่ะ)
   * เลือก Tier เป็น **Free** -> กด **Create New Project** (รอระบบสร้างเซิร์ฟเวอร์ประมาณ 1-2 นาที)
3. **การสร้างตารางข้อมูล (Migration)**:
   * เมื่อเข้าสู่หน้าแดชบอร์ดโครงการ -> ไปที่เมนูด้านซ้าย เลือกไอคอน **SQL Editor** (รูปสัญลักษณ์ `>_`)
   * คลิก **New Query**
   * คัดลอกโค้ด SQL จากไฟล์ [สคริปต์_ตารางฐานข้อมูล_Supabase.sql](./สคริปต์_ตารางฐานข้อมูล_Supabase.sql) ในโฟลเดอร์คู่มือไปวางทั้งหมด (ซึ่งครอบคลุมทั้งตารางระบบหลัก, ตารางโมดูล AI และสื่อการเรียนรู้ AR น้องชบาพาพิชิต รวมถึงตารางระบบทะเบียนเด็กในเขตพื้นที่บริการ ทร.14)
   * คลิกปุ่ม **Run** ด้านขวาล่าง
   * ตรวจสอบว่าระบบขึ้นคำว่า `Success. No rows returned` แสดงว่าตารางและระบบ RLS ทั้งหมดถูกสร้างขึ้นเรียบร้อยค่ะ
4. **เปิดการใช้งาน Storage (สำหรับเก็บโลโก้และไฟล์ชั่วคราว)**:
   * ไปที่เมนู **Storage** (ไอคอนรูปถังสีเทา)
   * คลิก **New Bucket** -> สร้างถังชื่อ **`system`** (ตั้งค่าเป็น Public) เพื่อเก็บโลโก้โรงเรียนและลายเซ็น ผอ.
   * คลิก **New Bucket** อีกครั้ง -> สร้างถังชื่อ **`temp_docs`** (ตั้งค่าเป็น Public) สำหรับพักไฟล์หนังสือนำส่งชั่วคราวขณะทำตราเกษียณ

## 🚀 ตอนที่ 2: การสมัครและติดตั้งเซิร์ฟเวอร์หลังบ้าน (Vercel Server Setup)

ตัวเซิร์ฟเวอร์หลังบ้านจะใช้ Vercel ในการรันเซิร์ฟเวอร์หลังบ้านและ Webhook ของแชทบอท LINE ค่ะ:

1. **ดึงซอร์สโค้ด (Fork)**:
   * สมัครบัญชี [GitHub](https://github.com)
   * เข้าไปที่ลิงก์ของโปรเจกต์ต้นแบบจากคุณครู: `https://github.com/officebkky-sketch/school-admin`
   * คลิกปุ่ม **Fork** ที่มุมขวาบน เพื่อคัดลอกโปรเจกต์ทั้งหมดมาเป็นของบัญชี GitHub ของคุณครูเอง
2. **เชื่อมต่อกับ Vercel**:
   * สมัครใช้งาน [https://vercel.com](https://vercel.com) (เข้าสู่ระบบด้วยบัญชี GitHub)
   * ในหน้าหลักของ Vercel คลิก **Add New...** -> **Project**
   * เลือกเชื่อมต่อกับ Repository ที่เพิ่ง Fork มาใน GitHub ของเรา (กด **Import**)
3. **ใส่คีย์ระบบ (Environment Variables)**:
   ก่อนจะกด Deploy ให้เลื่อนลงมาที่หัวข้อ **Environment Variables** และใส่คีย์ของโรงเรียนตนเองทีละตัวดังนี้ (คัดลอกจากหน้า Supabase -> Settings -> API):
   * **`VITE_SUPABASE_URL`**: ลิงก์ URL ของโครงการ Supabase
   * **`VITE_SUPABASE_ANON_KEY`**: คีย์ Anon (คีย์หน้าบ้าน)
   * **`SUPABASE_SERVICE_ROLE_KEY`**: คีย์ Service Role (คีย์หลังบ้านระดับ Admin สำหรับจัดการข้อมูลผู้ใช้)
   * **`LINE_CHANNEL_ACCESS_TOKEN`**: คีย์สำหรับติดต่อส่งข้อความ LINE (ขั้นตอนสร้างในตอนที่ 3)
   * **`VITE_GAS_URL`**: ลิงก์จาก Google Apps Script สำหรับเชื่อมต่อ Google Drive (ถ้าใช้คลาวด์จัดเก็บไฟล์นำส่ง)
   * **`OPENAI_API_KEY`**: คีย์สแกนเอกสารเสริม (ใส่หรือไม่ใส่ก็ได้)
4. **Deploy**:
   * เมื่อกรอกครบแล้ว กดปุ่ม **Deploy**
   * รอระบบแพ็กเกจระบบ 1-2 นาที เมื่อเสร็จแล้วจะพบภาพเฉลิมฉลองพร้อมลิงก์หน้าเว็บเซิร์ฟเวอร์ของคุณครู เช่น `https://schoolx-admin.vercel.app` (กรุณาจดลิงก์นี้ไว้ใช้งานด้วยนะคะ)

## 📁 ตอนที่ 2.5: การตั้งค่า Google Drive สำหรับอัปโหลดไฟล์ (Google Apps Script Setup)

หากโรงเรียนใหม่ต้องการจัดเก็บไฟล์สแกนหนังสือราชการไว้บน Google Drive ส่วนตัวของตนเอง:

1. **สร้างไฟล์ Script**: เข้าไปที่ [Google Drive](https://drive.google.com) ของบัญชีโรงเรียน -> คลิก **New (ใหม่)** -> **More (เพิ่มเติม)** -> **Google Apps Script**
2. **ใส่โค้ดระบบ**: คัดลอกซอร์สโค้ดจากไฟล์ [สคริปต์_Google_Drive.js](./สคริปต์_Google_Drive.js) ในโฟลเดอร์คู่มือไปวางแทนที่โค้ดเดิมทั้งหมดในหน้าต่างสคริปต์
3. **ตั้งชื่อโครงการ**: เปลี่ยนชื่อด้านซ้ายบนเป็น `School Admin Drive Uploader`
4. **เปิดการใช้งาน (Deploy)**:
   * คลิกปุ่ม **Deploy (การทำงานใช้จริง)** ที่มุมขวาบน -> เลือก **New deployment (การใช้งานใช้จริงรายการใหม่)**
   * คลิกไอคอนเฟืองเลือกประเภทการทำงานเป็น **Web app (เว็บแอป)**
   * **Execute as (เรียกใช้ในฐานะ)**: เลือกเป็น `Me` (บัญชีอีเมลโรงเรียนนี้)
   * **Who has access (ผู้มีสิทธิ์เข้าถึง)**: เลือกเป็น `Anyone (ทุกคน)` (จำเป็นต้องเลือกเพื่อให้ตัวแอป Desktop ส่งไฟล์เข้าไดรฟ์ได้โดยตรง)
   * คลิกปุ่ม **Deploy**
5. **ให้สิทธิ์การเข้าถึง**:
   * คลิกปุ่ม **Authorize access** -> เลือกบัญชี Google ของท่าน
   * กด **Advanced (ขั้นสูง)** -> คลิก **Go to School Admin Drive Uploader (unsafe)**
   * กด **Allow (อนุญาต)**
6. **คัดลอกลิงก์ใช้งาน**: คัดลอกค่า **Web app URL** ที่ได้มา (ลงท้ายด้วย `/exec`) นำมาใส่ในช่อง **`VITE_GAS_URL`** บนเว็บ Vercel และนำมากรอกช่อง **Google Drive GAS URL** ในแอปคอมพิวเตอร์ค่ะ

## 💬 ตอนที่ 3: การสร้างและเปิดระบบแชทบอท LINE OA (LINE OA Setup)

เพื่อให้ระบบมีแชทบอท "น้องชบา" ตอบโต้และแจ้งเตือนเข้าสู่กลุ่มไลน์ได้:

1. **สมัคร LINE OA**: เข้าไปสร้างบัญชีบอทที่ [LINE Official Account Manager](https://manager.line.biz)
2. **เปิดสิทธิ์ Messaging API**:
   * ไปที่ตั้งค่า (Settings) -> **Messaging API** -> กดเปิดใช้งาน
   * ไปที่เว็บ [LINE Developers Console](https://developers.line.biz) -> เข้าสู่ระบบด้วย LINE ส่วนตัว
   * คลิกเลือก Provider และเลือก Channel ของบอทที่เพิ่งสร้าง
3. **ขอ Token เชื่อมต่อ**:
   * ไปที่แท็บ **Messaging API** เลื่อนลงไปล่างสุดตรงหัวข้อ **Channel access token** -> กดปุ่ม **Issue**
   * คัดลอกค่า Token ยาวๆ นั้นมาใส่ในช่อง **`LINE_CHANNEL_ACCESS_TOKEN`** บนเว็บ Vercel (ตอนที่ 2)
4. **เปิดการรับ Webhook**:
   * ในแท็บ Messaging API ของ LINE Developers ให้หาช่อง **Webhook URL** -> นำลิงก์จาก Vercel มาใส่โดยลงท้ายด้วย `/api/line-webhook` เช่น:
     `https://schoolx-admin.vercel.app/api/line-webhook`
   * กดปุ่ม **Verify** (ต้องขึ้นคำว่า Success สีเขียวค่ะ)
   * มองหาปุ่ม **Use webhook** แล้วกดเปิด (Toggle ให้เป็นสีเขียว)
5. **ดึงบอทเข้ากลุ่มและเช็ค Group ID**:
   * เชิญตัวบัญชี LINE OA (บอทชบา) เข้าสู่กลุ่มแชทไลน์ของโรงเรียนที่ใช้แจ้งเตือน
   * พิมพ์ข้อความส่งเข้าไปในกลุ่มว่า: **`เช็คไอดีกลุ่ม`** (หรือภาษาอังกฤษ **`group id`**)
   * บอทชบาจะตอบกลับเป็นไอดีกลุ่มยาวๆ ที่ขึ้นต้นด้วยตัว `C` (เช่น `C718ba9882...`) ให้คัดลอกไอดีนี้ไว้ใช้งาน

## 🖥️ ตอนที่ 4: การใช้งานบนแอปพลิเคชันและการสลับโรงเรียน (Desktop App Usage)

เมื่อตั้งค่าระบบคลาวด์หลังบ้านเรียบร้อยแล้ว ให้เริ่มใช้งานแอปพลิเคชันดังนี้ค่ะ:

1. **เปิดโปรแกรม**: เปิดตัวโปรแกรม `.exe` ในเครื่องคอมพิวเตอร์
2. **หน้าจอตั้งค่าครั้งแรก**: หากเป็นการเปิดใช้งานครั้งแรกที่ยังไม่มีข้อมูลโรงเรียนใด ๆ ระบบจะแสดงหน้าจอ **"ตั้งค่าการเชื่อมต่อสถานศึกษา"** โดยอัตโนมัติ
3. **การลงทะเบียนโรงเรียนแรก**:
   * คลิกปุ่ม **"➕ เพิ่มโรงเรียนใหม่"**
   * กรอกข้อมูลที่ได้เตรียมไว้ (ชื่อโรงเรียน, Supabase URL, Supabase Anon Key, Vercel Webhook URL, และ GAS URL)
   * คลิกปุ่ม **"บันทึกข้อมูล"**
   * **ระบบจะทำระบบสลับพาคุณครูย้อนกลับไปที่หน้าล็อกอินโดยอัตโนมัติทันทีค่ะ!**
4. **การเพิ่มโรงเรียนเพิ่มเติมนอกเหนือจากโรงเรียนแรก**:
   * ในหน้าจอล็อกอิน ให้คลิกปุ่ม **"จัดการ"** สีเขียวตรงมุมขวาบนของกล่องเลือกสถานศึกษา เพื่อเข้าสู่หน้าจอการตั้งค่าเชื่อมต่อ
   * คลิกปุ่ม **"➕ เพิ่มโรงเรียนใหม่"** และกรอกคีย์ของโรงเรียนอื่น ๆ เพิ่มเติม
   * เมื่อกดบันทึกเสร็จแล้ว ให้คลิกปุ่ม **"ย้อนกลับไปเข้าสู่ระบบ"** ที่มุมขวาบนของหน้าจอแอปพลิเคชัน
5. **การสลับโรงเรียนเพื่อเข้าใช้งาน**:
   * ในหน้าจอล็อกอิน คุณครูสามารถเลือกโรงเรียนที่ต้องการเข้าใช้งานได้จาก **กล่องเลือกสถานศึกษา (Dropdown)** 
   * เมื่อเข้าสู่ระบบแล้ว หากต้องการเปลี่ยนไปทำระบบของโรงเรียนอื่น ให้คลิกปุ่ม **"🔄 สลับโรงเรียน"** บริเวณด้านล่างของชื่อโรงเรียนในแถบเมนูด้านซ้าย (Sidebar) เพื่อเปลี่ยนโรงเรียนอย่างรวดเร็วค่ะ! 🌸✨

## 🔑 ตอนที่ 5: การแต่งตั้งผู้ดูแลระบบคนแรก (First Admin Activation)

เมื่อติดตั้งและเพิ่มโรงเรียนใหม่ลงในแอปเป็นที่เรียบร้อยแล้ว ในการสมัครใช้งานครั้งแรก **คุณครูผู้สมัครบัญชีแรกจะยังไม่ได้สิทธิ์เป็น Admin โดยอัตโนมัติ** เนื่องจากระบบความปลอดภัยจะกักผู้สมัครใหม่ทุกคนไว้ที่สถานะ **`'guest'` (ผู้ใช้รออนุมัติ)** เสมอ

คุณครูที่เป็นผู้ดูแลระบบส่วนกลาง จะต้องเข้าไปอนุมัติสิทธิ์ Admin ให้กับตนเอง (หรือบัญชีแรก) โดยตรงผ่าน **Supabase Dashboard** ตามวิธีด้านล่างนี้ค่ะ:

### วิธีที่ 1: ตั้งค่าผ่านแถบ Table Editor (แนะนำ)
1. เข้าไปที่แดชบอร์ดโครงการของโรงเรียนคุณครูในเว็บ [https://supabase.com](https://supabase.com)
2. เมนูด้านซ้ายเลือก **Table Editor** (ไอคอนตาราง) -> เลือกตาราง **`profiles`**
3. ค้นหาแถวของบัญชีผู้ใช้งานแรกที่คุณครูได้ลงทะเบียนไว้
4. ดับเบิ้ลคลิกแก้ไขค่าข้อมูลในตารางดังนี้:
   * คอลัมน์ **`role`**: ดับเบิ้ลคลิกแล้วแก้ไขจาก `guest` เป็น **`admin`**
   * คอลัมน์ **`status`**: ดับเบิ้ลคลิกแล้วแก้ไขเป็น **`active`**
5. กดบันทึกการเปลี่ยนแปลง

### วิธีที่ 2: ตั้งค่าผ่านการรันคำสั่ง SQL (SQL Editor)
1. เข้าไปที่โครงการของคุณครูใน Supabase -> เมนูด้านซ้ายเลือก **SQL Editor** (รูปสัญลักษณ์ `>_`)
2. คลิก **New Query**
3. คัดลอกและนำคำสั่ง SQL ด้านล่างนี้ไปวาง (กรุณาแก้ไขอีเมลให้ตรงกับบัญชีที่สมัครไว้):
   ```sql
   UPDATE profiles 
   SET role = 'admin', status = 'active' 
   WHERE email = 'admin@your-school.ac.th';
   ```
4. คลิกปุ่ม **Run** ที่มุมขวาล่าง

เมื่อดำเนินการเสร็จเรียบร้อยแล้ว คุณครูจะสามารถล็อกอินเข้าสู่ระบบได้ด้วยสิทธิ์ **Admin** ทันที และสามารถคลิกเข้าไปที่เมนู **"จัดการสิทธิ์ผู้ใช้งาน"** ภายในแอปพลิเคชันเพื่ออนุมัติสิทธิ์ให้แก่คุณครูคนอื่นๆ ที่จะสมัครใช้งานถัดไปได้เองจากหน้าจอของโปรแกรมค่ะ 💡🔒

### 2. การอัปเกรดระบบ AI และการแก้ไขข้อผิดพลาด - *อัปเดตเมื่อวาน*
* **เปลี่ยนโมเดลหลักเป็น Gemini 3.1 Flash-Lite:** อัปเกรดและปรับเปลี่ยนการเรียกใช้งานอันดับ 1 เป็นโมเดลรุ่น Flash-Lite สำหรับประมวลผลด่าน AR และฟังก์ชันทั่วไป เพื่อลดผลกระทบจาก Rate Limit (429) และประหยัดค่าโควต้าการใช้งานฟรี
* **แก้ไขข้อกำหนด CamelCase สำหรับ REST API:** แก้ไขโครงสร้างใน `aiService.ts` โดยปรับพารามิเตอร์ `generationConfig` ให้เป็น CamelCase (`responseMimeType`, `maxOutputTokens`) และเปลี่ยนชื่อฟิลด์จาก `system_instruction` เป็น `systemInstruction` เพื่อให้เป็นไปตามข้อกำหนดล่าสุดของ Google API
* **จำแนกสิทธิ์ผู้ใช้ด่าน AR:** ปรับปรุงให้ครูทั่วไปมองเห็นเฉพาะด่านบทเรียนของตนเอง ส่วนผู้บริหาร (ผอ.) และฝ่ายวิชาการสามารถมองเห็นและจัดการด่านบทเรียนของครูทุกคนได้ทั้งหมด
* **แก้ไขปัญหา Supabase 400 Bad Request:** บังคับและตรวจสอบให้ฟังก์ชันการบันทึกสร้างรหัส ID ในฟอร์แมต **UUID v4** ก่อนจัดเก็บข้อมูลออนไลน์เสมอ เพื่อความเข้ากันได้ดีกับคีย์หลักในฐานข้อมูล Supabase

### 3. ระบบความปลอดภัยและสิทธิ์ RLS (Security & Access Control) - *อัปเดตวันนี้*
* **การอนุมัติและจัดการค่าสาธารณูปโภค:** ปรับปรุงนโยบาย RLS ในตาราง `utilities` และ `utility_items` ให้ผู้อำนวยการ (`director`) และผู้ดูแลระบบ (`admin`) สามารถกดอนุมัติและลบรายการเบิกจ่ายสาธารณูปโภคที่ผู้อื่นสร้างได้ พร้อมกับปรับปรุงหน้าจอ [Utilities.tsx](../src/pages/Utilities.tsx) ให้แสดงผลและกรองปุ่มการอนุมัติ/ลบตามระดับบทบาทการใช้งานจริง
* **ปิดช่องโหว่ความปลอดภัยระดับวิกฤต (Critical Security Vulnerabilities):**
  * **Table publicly accessible:** เปิดใช้งาน Row-Level Security (RLS) บนตารางจัดสรรงบประมาณ `budget_allocations` ป้องกันการเข้าถึงและแก้ไขข้อมูลการเงินสถานศึกษาจากภายนอก
  * **Sensitive data publicly accessible:** ปรับปรุงนโยบายสิทธิ์การเข้าอ่านตาราง `profiles` (ข้อมูลคุณครูและไฟล์ลายเซ็นดิจิทัล ผอ.) และตาราง `settings` (Gemini API Key และ LINE Token) จากเดิมที่เปิดเป็นสาธารณะ (Public SELECT) ให้เปลี่ยนมาจำกัดสิทธิ์เฉพาะผู้ใช้งานที่ผ่านการยืนยันตัวตนเข้าระบบแล้วเท่านั้น (`auth.uid() IS NOT NULL`) ป้องกันการสแกนเก็บข้อมูลส่วนบุคคลและป้องกันคีย์ API รั่วไหลได้อย่างสมบูรณ์แบบ

### 4. ระบบลงทะเบียนนักกีฬา และระบบส่งแผนการสอน (Athletics & Lesson Plans) - *อัปเดตล่าสุด v1.1.14*
* **ระบบลงทะเบียนนักกีฬา (ระดับตำบลและระดับจังหวัด):**
  * **ฐานข้อมูล:** ตาราง `athletics_registrations` (รวมอยู่ในไฟล์ SQL ของคู่มือเรียบร้อย) รองรับคอลัมน์ `is_substitute` (ตัวจริง/ตัวสำรอง) และคอลัมน์ใหม่ `competition_type` เพื่อแยกรายการแข่งขันระหว่างระดับตำบล (`'local'`) และระดับจังหวัด (`'provincial'`) พร้อมดัชนีเพิ่มความเร็วในการสืบค้น
  * **การแก้ไขดึงข้อมูลเพศ:** ปรับปรุงตัวแปลงข้อมูลเพศของนักเรียนเพื่อรองรับตัวย่อ `"ช"` และ `"ญ"` จากตารางฐานข้อมูลหลัก ป้องกันข้อมูลเพศผิดพลาดในใบรับรอง
  * **ปรับปรุงรูปแบบสิ่งพิมพ์ตามระเบียบราชการ:**
    * บังคับใช้ขนาดฟอนต์ **16pt (TH Sarabun)** บนย่อหน้าข้อความโดยตรง ป้องกันสไตล์ภายนอกเขียนทับ
    * ปรับระยะห่างของกล่องลายเซ็นและคำรับรองของ ผอ. ให้กระชับสวยงาม (ลด `lineHeight` เหลือ `1.4`)
    * ซ่อนเครดิตส่วนท้ายของระบบ (`IdentityFooter`) ด้วยการใส่คลาส `no-print` ขณะสั่งปริ้น เพื่อป้องกันปัญหาหน้ากระดาษเกินหรือเกิดหน้าว่างหน้าสุดท้าย
  * **การแปลงเลขไทยและค่าไดนามิก:** แปลงตัวเลขในใบรับรอง (วันเกิด, ปี พ.ศ. เกิด, อายุ, ระดับชั้น/ห้องเรียน) เป็น **"ตัวเลขไทย"** ทั้งหมดโดยอัตโนมัติ และแสดงผลปี พ.ศ. พร้อมคำนวณครั้งที่จัดการแข่งขันระดับจังหวัดแบบไดนามิกอิงตามปีที่ผู้ใช้เลือก (คำนวณจาก `ปีการศึกษาที่เลือก - 2492` เช่น ปีการศึกษา ๒๕๖๙ คือ ครั้งที่ ๗๗)

* **ระบบส่งแผนการสอน (Lesson Plans System):**
  * **ฐานข้อมูล:** เพิ่มตาราง `lesson_plans` และตารางบันทึกกิจกรรม `lesson_plan_logs` (รวมอยู่ในสคริปต์ SQL หลักแล้ว) พร้อมกำหนดสิทธิ์ RLS ให้ครูสามารถส่งและลบแผนการสอนของตนเองได้ ส่วนหัวหน้าวิชาการ/ผอ./แอดมิน สามารถเข้ามาตรวจและอนุมัติแผนการสอนได้
  * **ใบเสนออนุมัติ:** รองรับการพิมพ์ใบเสนออนุมัติแผนการสอนขนาด A4 แนวตั้ง จัดข้อความแบบบันทึกราชการกึ่งกลางหน้ากระดาษ พร้อมแสดงตราครุฑ (ขนาด 1.5 cm) ที่มุมซ้ายบนอย่างถูกต้องและสวยงามตามรูปแบบงานสารบรรณ
  * **การสลับสิทธิ์การมองเห็น:** ครูทั่วไปจะมองเห็นเฉพาะแถบเมนูส่งแผนการสอนของตนเอง (เปลี่ยนชื่อเมนูเป็น "งานแผนการสอน") ส่วนระดับหัวหน้าวิชาการขึ้นไปจะมองเห็นเมนูจัดการทะเบียนวิชา ตารางสอน และการมอบหมายงานทั้งหมดตามปกติ

### 5. ระบบรายงานเด็กเข้าเรียน ป.1 (แนบ 386) - *อัปเดตล่าสุด v1.1.15*
* **แบบรายงานบัญชีรายชื่อเด็กเข้าเรียนเกณฑ์บังคับ (แนบ 386):**

  * **การแก้ไขข้อมูลสด (Inline Editing):** คุณครูสามารถดับเบิลคลิก/พิมพ์แก้ไขข้อมูลประวัติเด็ก เช่น ชั้นเรียน, ชื่อบิดา-มารดา, ผู้ปกครอง และโรงเรียนปลายทางบนตารางพรีวิวก่อนสั่งพิมพ์ได้ทันที พร้อมระบบซ่อนกรอบอินพุตตอนพิมพ์ออกจริง
  * **ปุ่มบันทึกข้อมูลย้อนกลับ:** เพิ่มปุ่มสำหรับบันทึกข้อมูลที่คุณครูพิมพ์แก้ไขในตาราง ส่งกลับไปอัปเดตและบันทึกจริงในระบบฐานข้อมูล Supabase ถาวรทันที ป้องกันข้อมูลสูญหาย
  * **การปลดล็อก layout และซ่อนเมนูขณะพิมพ์:** เขียนคำสั่ง DOM JavaScript และ CSS @media print ระดับ Global เพื่อสั่งซ่อนแถบเมนูข้าง (Sidebar) และแถบเมนูบน (Header) อัตโนมัติ ป้องกันปัญหากระดาษเกิน หน้าว่าง และพิมพ์ติดแถบเมนูควบคุมของระบบแอปพลิเคชัน

### 6. ระบบ Smart OCR, RAG Memory & Auto Task Assignment - *อัปเดตล่าสุด v1.1.16*
* **โมดูลการทำงานใหม่:**
  * **Smart OCR (Gemini Multimodal):** สแกนอ่านข้อความจากไฟล์ภาพและเอกสาร PDF ของหนังสือรับโดยอัตโนมัติ เพื่อแยกวิเคราะห์หัวข้อ, จากหน่วยงานใด, ดึงกำหนดส่งงาน (action_deadline) และระบุแนะนำครูผู้รับผิดชอบงานที่เหมาะสมตามเนื้อหาของหนังสือนั้นๆ
  * **ความจำ RAG (RAG Memory):** บันทึกข้อความสกัดจากหนังสือรับลงในคลังความรู้ `school_knowledge` ทำให้ "น้องชบา AI" ใน Telegram จำเนื้อหาของเอกสารย้อนหลังได้ตลอดกาลและตอบแชทครูจากเนื้อหาจริงในเอกสารได้แม่นยำ 100%
  * **ปุ่มกดเกษียณงานในคลิกเดียว (Smart Assign via Telegram):** ผู้อำนวยการสามารถกดมอบหมายงานครูด้วยปุ่มบน Telegram ได้ทันที บอทจะส่งข้อความแจ้งเตือนส่วนตัวครู และส่งรายงานผลเข้ากลุ่มกลางโรงเรียนโดยอัตโนมัติเมื่อดำเนินการรับทราบ/รายงานผล
* **สคริปต์ SQL Migration สำหรับการอัปเดต (กรุณารันใน SQL Editor ของ Supabase):**
  ```sql
  -- 1. เพิ่มคอลัมน์ในตาราง incoming_docs
  ALTER TABLE incoming_docs 
    ADD COLUMN IF NOT EXISTS extracted_text TEXT,
    ADD COLUMN IF NOT EXISTS action_deadline TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS suggested_assignee_id UUID REFERENCES teachers(id) ON DELETE SET NULL,
    ADD COLUMN IF NOT EXISTS auto_processed_at TIMESTAMPTZ;

  -- 2. เพิ่มคอลัมน์ในตาราง school_knowledge สำหรับเชื่อมโยงหนังสือรับ (RAG)
  ALTER TABLE school_knowledge
    ADD COLUMN IF NOT EXISTS source_doc_id UUID REFERENCES incoming_docs(id) ON DELETE CASCADE,
    ADD COLUMN IF NOT EXISTS source_type TEXT DEFAULT 'manual';

  -- 3. เพิ่มคอลัมน์การตั้งค่า Cloud Vision API ในตาราง settings
  ALTER TABLE settings
    ADD COLUMN IF NOT EXISTS google_vision_api_key TEXT;

  -- 4. สร้าง Index เพื่อเพิ่มความเร็วในการค้นหา
  CREATE INDEX IF NOT EXISTS idx_incoming_docs_action_deadline ON incoming_docs(action_deadline);
  CREATE INDEX IF NOT EXISTS idx_school_knowledge_source_doc ON school_knowledge(source_doc_id);
  ```
